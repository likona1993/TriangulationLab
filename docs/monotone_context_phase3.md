## Существующие типы (в других заголовках проекта)

- `Point2<T>` — поля `x`, `y`; есть `operator-` и метод
  `T cross(const Point2& other) const` (произведение двух векторов:
  `x*other.y - y*other.x`)
- `Polygon2<T>` — `size()`, `operator[]`
- `Triangle2<T>`, `TriangulationResult<T>` (есть поле `error_message`), `DebugStep<T>`
- `Edge` — агрегат `{from, to}` типа `size_t`
- `EPSILON<T>`
- `isSimplePolygon(poly, eps)`
- `isConvex(prev, curr, next, eps)` → `cross(curr-prev, next-curr) > eps` (строго левый поворот)
- `computeXIntersection(p1, p2, currentY)` — с защитой от деления на 0 и зажимом `t ∈ [0,1]`;
  для горизонтального ребра возвращает **левый конец** `std::min(p1.x, p2.x)`
- Функция нормализации ориентации в **CCW** существует и вызывается до алгоритма

## Мои алиасы и хелперы (уже введены)

```cpp
using VertexIndex   = size_t;
using Diagonal      = std::pair<VertexIndex, VertexIndex>;   // фаза 1
using MonotonePiece = std::vector<VertexIndex>;              // фаза 2
using Triangles     = std::vector<Triangle2<T>>;

enum VertexType { START, END, SPLIT, MERGE, REGULAR };

// Порядок sweep line: y убывает, при равной y — x возрастает.
// Эквивалент чуть наклонённой прямой y - εx = const.
// Используется ВЕЗДЕ: и в сортировке вершин, и в classifyVertex.
static bool isAbove(const Point2<T>& a, const Point2<T>& b) {
  if (std::abs(a.y - b.y) > EPSILON<T>) return a.y > b.y;
  return a.x < b.x;
}

// Знак поворота o -> a -> b. > 0 — против часовой.
static T cross(const Point2<T>& o, const Point2<T>& a, const Point2<T>& b) {
  return (a - o).cross(b - o);
}

// Знаковая площадь замкнутого контура, заданного индексами
static T signedArea(const Polygon& poly, const std::vector<VertexIndex>& loop);
```

## Что уже сделано и разобрано

### Фаза 1 (закрыта)

1. **Ориентация** — полигон приводится к CCW перед работой.

2. **`classifyVertex`** — исправлен: раньше `convex` вычислялся, но не
   использовался, из-за чего SPLIT и MERGE не возвращались никогда.

   | соседи | выпуклая | вогнутая |
   |---|---|---|
   | оба ниже (лок. максимум) | START | SPLIT |
   | оба выше (лок. минимум) | END | MERGE |
   | один выше, один ниже | REGULAR | REGULAR |

3. **`HelperMap`** — был `std::map<Edge, VertexIndex, EdgeCmp<T>>` → это UB
   (компаратор зависит от `currentY`, порядок ключей менялся по ходу sweep).
   Заменён на статический компаратор `EdgeLess` (по `from`, затем `to`).

4. **`StatusSet`** (`std::set<Edge, EdgeCmp<T>>`) — корректен только при
   инварианте: **в статусе лежат ТОЛЬКО нисходящие рёбра**.
   Ребро `e(a→b)` нисходящее ⟺ `isAbove(poly[a], poly[b])`.
   Вставляется на верхнем конце, удаляется на нижнем.

5. **helper(e)** — самая нижняя из уже обработанных вершин, до которой из области
   справа от `e` можно безопасно провести диагональ («потолок трапеции»).

   Главная асимметрия:
   - **SPLIT** чинится **сразу** (партнёр — helper левого ребра, он уже обработан).
   - **MERGE** чинится **отложенно**: она записывается в helper — это **долг**.
     Первая же вершина, которая позже этого helper'а коснётся, обязана провести
     к ней диагональ. Отсюда проверка `types[helper] == MERGE` в END, MERGE и
     обеих ветках REGULAR.

6. **Хендлеры** через три кирпичика: `closeEdge` (erase + `helpers.erase`!),
   `openEdge` (insert, helper = vi), `updateLeftHelper` (`findLeftEdge` +
   `tryCloseMerge` + перезапись helper'а).

   | | closeEdge | openEdge | updateLeftHelper | безусл. диагональ |
   |---|---|---|---|---|
   | START | | ✓ | | |
   | END | ✓ | | | |
   | SPLIT | | ✓ | ✓ | **✓** к helper левого ребра |
   | MERGE | ✓ | | ✓ | |
   | REGULAR, левая цепь (`prev` выше) | ✓ | ✓ | | |
   | REGULAR, правая цепь | | | ✓ | |

7. Состояние sweep передаётся структурой `SweepCtx` (указатели на poly, types,
   status, helpers, diagonals, `T* currentY`). `currentY` — ОДИН экземпляр,
   на который смотрит и `EdgeCmp`, и `findLeftEdge`; обновляется **до** хендлера.

### Фаза 2 (закрыта)

`splitIntoMonotone(poly, diagonals)` → `std::vector<MonotonePiece>`:

1. Строим планарный граф: рёбра границы + диагонали, каждое в **обе стороны**.
2. Соседей каждой вершины сортируем **по углу CCW**. Через `half` + `cross`,
   БЕЗ `atan2`:
   - `half(q) = 1`, если вектор `p→q` строго вниз, или строго влево по оси −x;
     иначе `0`. Это «разрез круга», аналог скачка atan2 через ±π.
   - внутри одной половины угол между векторами < 180°, поэтому знак `cross`
     задаёт корректный порядок (без `half` отношение было бы циклическим → UB в `std::sort`).
3. Обход граней: пришли в `b` по ребру `a→b` → следующая вершина — сосед `b`,
   **предыдущий по кругу** от `a` в CCW-списке (= поворот по часовой стрелке):
   ```cpp
   k = indexOf(b, a);
   c = adj[b][(k + adj[b].size() - 1) % adj[b].size()];
   ```
   Помечаем **направленные** рёбра как посещённые; каждое проходится ровно 2 раза.
4. Внутренние грани обходятся CCW (площадь > 0), внешняя — CW (площадь < 0).
   Отбрасываем по знаку `signedArea`.

**Открытые TODO фазы 2** (не блокируют, делать после тестов):

- `signedArea`: сдвигать точки на `loop[0]` перед суммированием (точность).

### Инварианты (assert, не if — провал означает баг в коде, а не плохой вход)

- в конце фазы 1: `status.empty() && helpers.empty()`
- всегда: `status.size() == helpers.size()`
- фаза 2: `pieces.size() == diagonals.size() + 1` (k диагоналей режут простой
  полигон ровно на k+1 кусков) — самая ценная проверка
- сумма площадей кусков == площадь полигона
- каждый кусок монотонен: у него **ровно один локальный максимум и ровно один
  локальный минимум** в sweep-порядке (выпуклость проверять не нужно —
  SPLIT это лишний максимум, MERGE — лишний минимум)

Функции-проверки объявляем **без** `#ifndef NDEBUG` — шаблонный метод, который
никто не вызывает, всё равно не инстанцируется, а API остаётся одинаковым в
debug и release.

## Сквозной тестовый пример

Прямоугольник 10×10 с треугольными вырезами сверху и снизу. Обход CCW:

```
v0=(0,0)  v1=(3,0)  v2=(5,4)  v3=(7,0)  v4=(10,0)
v5=(10,10) v6=(7,10) v7=(5,6) v8=(3,10) v9=(0,10)
```

```
      9┌────────┐8        6┌────────┐5     y=10
       │         ╲        ╱         │
       │          ╲      ╱          │
       │            7 (MERGE)       │      y=6
       │            ║ ← диагональ   │
       │            2 (SPLIT)       │      y=4
       │          ╱    ╲            │
      0└────────┘1      3└────────┘4      y=0
```

Проверенные значения:

- **sweep-порядок:** `9, 8, 6, 5, 7, 2, 0, 1, 3, 4`
- **типы (индексы 0..9):** REGULAR, END, SPLIT, REGULAR, END, REGULAR, START, MERGE, REGULAR, START
- **нисходящие рёбра:** `e(9→0)`, `e(6→7)`, `e(2→3)`, `e(0→1)`, `e(3→4)`
- **диагонали:** ровно одна — `{2, 7}`, отрезок (5,4)–(5,6)
- **грани после обхода:**
  - A = `[0, 1, 2, 7, 8, 9]`, площадь +42 → кусок
  - B = `[0, 9, 8, 7, 6, 5, 4, 3, 2, 1]`, площадь −84 → внешняя, отброшена
  - C = `[2, 3, 4, 5, 6, 7]`, площадь +42 → кусок
- **итог:** `pieces == { {0,1,2,7,8,9}, {2,3,4,5,6,7} }`, площадь полигона 84

Полезная тонкость: `v9` — это START, а не REGULAR, потому что при
лексикографическом порядке `v8=(3,10)` считается **ниже** `v9=(0,10)`
(та же y, но x больше). Симметрично `v6` — START, а `v5` — REGULAR.
